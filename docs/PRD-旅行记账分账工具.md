# 旅行记账分账工具 — 产品需求文档

## 1. 背景与目标

5 人小团体出游，需要一个轻量工具记录旅途开销，旅行结束后一键 AA 结算，给出"谁该给谁补多少钱"及计算依据。

**核心定位：** 纯前端 H5，移动端优先，无需登录，数据存浏览器 localStorage，通过 JSON 导出/导入实现多人数据对齐。

## 2. 用户与场景

- **使用者：** 出游团体中的一人（主要记账人），或多人各自录入后导出合并
- **场景：** 旅途中随时掏出手机记账——餐厅买单、门票、打车、零食等
- **结算时机：** 旅行结束后，大家核对最终账单，一键出结果

## 3. 范围

### 必须做

1. 初始化旅行 — 设定旅行名称、成员人数和昵称（默认 5 人）
2. 记账 — 记录每笔费用的用途、时间、支付人、金额、受益人；支持删除和修改
3. 结算 — 一键计算谁该给谁多少钱，给出完整计算依据
4. 导出/导入 JSON — 导出账单为 JSON 文件或复制到剪贴板；支持导入 JSON 覆盖本地数据
5. 重置 — 支持清除全部数据重新开始，需二次确认防误触
6. 移动端友好 — 适配手机屏幕，触控操作

### 可以做（本次不做，后续迭代）

1. 实时当前结算结果（记账页即预览）
2. 每日自动汇总当天开销
3. 账目相似度防重提示
4. 支出金额分类统计

### 本次不做

1. 后端存储、云同步
2. 用户登录和权限
3. 数据加密

## 5. 数据对象

### 5.1 Trip（旅行）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | 是 | 旅行名称，默认 "我的旅行" |
| members | Member[] | 是 | 成员列表，长度 2~20 |
| expenses | Expense[] | 是 | 费用列表，初始为空 |
| createdAt | string(ISO 8601) | 自动 | 创建时间 |

### 5.2 Member（成员）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | 自动 | 唯一标识，UUID |
| name | string | 是 | 昵称，1~10 字符，不可为空 |

### 5.3 Expense（费用）

| 字段 | 类型 | 必填 | 枚举/约束 | 说明 |
|---|---|---|---|---|
| id | string | 自动 | UUID | 唯一标识 |
| purpose | string | 是 | 1~50 字符 | 用途描述 |
| amount | number | 是 | > 0，最多两位小数 | 支付金额 |
| payerId | string | 是 | 必须是 members 中的 id | 支付人 |
| beneficiaryIds | string[] | 是 | 至少 1 个，每个必须在 members 中 | 受益人列表 |
| createdAt | string(ISO 8601) | 自动 | — | 记录时间 |

### 5.4 SettlementResult（结算结果，计算产物，不持久化）

| 字段 | 类型 | 说明 |
|---|---|---|
| memberBalances | MemberBalance[] | 每人净收支 |
| transactions | Transaction[] | 转账方案 |

**MemberBalance：**

| 字段 | 类型 | 说明 |
|---|---|---|
| memberId | string | 成员 id |
| memberName | string | 成员昵称 |
| paid | number | 该人总共支付了多少 |
| owed | number | 该人总共应承担多少 |
| balance | number | 净额（正=应收，负=应付） |

**Transaction：**

| 字段 | 类型 | 说明 |
|---|---|---|
| fromId | string | 付款方成员 id |
| fromName | string | 付款方昵称 |
| toId | string | 收款方成员 id |
| toName | string | 收款方昵称 |
| amount | number | 转账金额 |

## 6. 业务规则

### 6.1 初始化

- 默认创建 5 名成员，昵称默认值："成员1"~"成员5"，用户可修改
- 成员数量范围：2 ~ 20
- 每个成员昵称不可为空，不可重复
- 初始化后成员列表不可增删（简化设计，后续可扩展）

### 6.2 记账校验

- `purpose`：1~50 字符，不可为空
- `amount`：数字，> 0，最多保留两位小数
- `payerId`：必须为当前旅行成员之一
- `beneficiaryIds`：至少选中 1 人，所有人必须在成员列表中
- `createdAt`：默认当前时间，用户可手动修改（用于补录之前的账）

### 6.3 删除与修改

- 所有费用记录支持修改（点击进入编辑态）
- 删除需确认弹窗
- 修改/删除后结算结果实时失效，需重新结算

### 6.4 结算算法

**第一步：计算净收支**

对每位成员：
```
已支付总额(paid) = Σ(该人作为 payer 的 expense.amount)
应承担总额(owed)= Σ(该人作为 beneficiary 时，expense.amount ÷ 该笔受益人数量)
净额(balance) = paid - owed
```
- balance > 0：该人垫付过多，应收钱
- balance < 0：该人消费多付的少，应付钱
- balance = 0：平账

**第二步：最小转账笔数（贪心算法）**

1. 将成员分为债权人（balance > 0）和债务人（balance < 0）
2. 各按 |balance| 从大到小排序
3. 最大债权人和最大债务人之间结算：转账金额 = min(债权, |债务|)
4. 谁被清完就从列表移除
5. 重复直到所有余额归零
6. 结果四舍五入到分（0.01）

### 6.5 导入/导出

**导出：**
- 支持"复制到剪贴板"和"下载 JSON 文件"两种方式
- 导出内容为完整的 Trip 对象 JSON

**导入：**
- 支持"从剪贴板粘贴"和"选择 JSON 文件"两种方式
- 导入前校验 JSON 结构合法性
- 导入会覆盖当前本地数据，需二次确认
- 校验规则：members 长度合法、expenses 字段完整

### 6.6 重置

- 清除所有数据（回到初始化页）
- 需经过两次确认：第一次弹出确认框，第二次要求用户输入"确认重置"四个字

### 6.7 状态管理

- 所有数据通过一个 Vue composable (`useTripStore`) 管理
- 数据变更自动写入 localStorage
- 应用启动时从 localStorage 读取，无数据则跳转初始化页
- 页面路由守卫：未初始化时跳转初始化页

## 7. 页面与流程

### 页面路由

| 路径 | 页面 | 说明 |
|---|---|---|
| `/` | 初始化页 | 设定旅行名称和成员 |
| `/expense` | 记账页 | 记账表单 + 历史列表 |
| `/settlement` | 结算结果页 | 谁该给谁多少钱 |
| `/detail` | 结算依据页 | 每笔账的分摊明细 |

### 交互流程

```
初始化 → 记账（可多次、可增删改） → 结算 → 查看依据
                  ↑                      │
                  └──── 返回继续记账 ←────┘
```

## 8. 验收标准

模拟一次 5 人旅行，包含以下场景：

1. **基础记账**：添加一笔全员均摊的支出，验证数据正确保存
2. **部分分摊**：添加一笔仅 3 人受益的支出，验证受益人可正确选择
3. **修改记录**：修改一笔已有的支出，验证更新生效
4. **删除记录**：删除一笔支出并确认，验证列表更新
5. **结算正确性**：手动验算一笔简单账（如 A 付 100 全员均摊），确认计算结果正确
6. **最小转账**：构造多笔交叉垫付，验证结算给出最优转账方案
7. **导出导入**：导出一份 JSON，在另一浏览器或无痕窗口导入，验证数据一致
8. **重置**：触发重置，验证二次确认后数据清空
9. **移动端**：在手机浏览器打开，验证可正常记账和结算
