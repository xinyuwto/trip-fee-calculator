## 已实现

旅行记账 AA 分账工具，纯前端 Vue 3 SPA，功能完整可用。

### 页面（4 个）
| 路由 | 视图 | 功能 |
|------|------|------|
| `/` | InitView | 设定旅行名称、成员人数（2-20）、成员姓名 |
| `/expense` | ExpenseView | 支出增删改（10 种费用分类 + 备注）、JSON 导出导入、重置数据 |
| `/settlement` | SettlementView | 总支出、每人净额、最少转账方案、"结算依据"入口 |
| `/detail` | DetailView | 按成员分 tab 的结算依据：净额卡片、转账任务、与他人往来、解释说明 |

### 数据层
- `src/stores/trip.js` — 单例 composable，deep watch 自动写 localStorage
- 金额用**整数分**存储，无浮点精度问题
- 添加/修改操作成功后 toast 提示（"添加成功"/"修改成功"，2 秒自动消失）
- 导入/导出：剪贴板 + JSON 文件，校验 + 二次确认

### 分账算法
- `analyzeSettlement()` — 按成员维度输出净额、应收/应付来源、与他人往来、解释说明
- `calculateSettlement()` — 每笔支出在受益人之间**整数均摊**，贪婪匹配债权人/债务人 → 最小转账笔数

### 同步功能（合并式同步 v2）
- 8 位共享码：记账页头部「同 步」开启并生成；InitView 新增「加 入 旅 行」入口，同伴输入同步码 → 摘要确认（含覆盖二次确认）→ 选身份 → 进入记账页自动拉取
- **自动同步**：新增/修改/删除、进入页面、刷新后自动触发；引擎串行队列保证同一时刻 ≤1 个在途请求，快速连续操作自动排队合并
- **逐条合并（LWW）**：客户端与服务端按记录逐条合并，本地新取本地、远端新取远端、时间全等取远端（确定性）；删除以墓碑（deletedIds）传播；trip 元数据同规则 LWW。无「用我的覆盖」整包冲突弹窗（v1 冲突视图已删除）
- **去重确认**：四要素（支付人+受益人集合+金额+项目）相同的记录视为疑似重复，受益人顺序不同不参与判断；表单提交时本地即时弹「疑似重复」；自动同步发现服务端疑似重复时 SyncDialog 自动弹出，逐条裁决「是重复，去重 / 保留两条」
- **状态指示**：记账页头部状态 chip —— 同步中 / 已同步 / 同步失败 · 点击重试 / 待确认 N 条；失败时本地数据不动，恢复网络后刷新或重试即补传积压变更
- 后端：CloudBase（腾讯云开发）体验版 —— 云函数 `trip-sync`（HTTP 函数，mode:merge 端点）+ `trips` 集合（ADMINONLY 权限）；体验版到期时间 **2027-01-23**
- 兜底：JSON 导入/导出保留为离线兜底，无网络时仍可跨设备传递数据
- 同步状态存于 `trip-fee-calculator-sync`（localStorage）：同步码、我的身份、上次同步时间（v1 的 baseRevision 已废弃）
