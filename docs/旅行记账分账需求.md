# 背景：
我们5人出行，需要有一个简便的工具计算开销，方便旅行结束之后AA分摊费用。

# ⽤户与场景：
旅行过程中，方便的记账，在AA的规则下，最终可以一键结算谁需要向谁付多少钱，并给出计算依据。在旅途中使用，因此需要轻量的H5页面，注意移动端浏览友好。会在旅途中随时记账，界面需要简洁，只记录最核心必要的内容，减少用户的记录负担。注意不是所有的开支都是一人支付全部人使用，可能存在一人支付只有团体内部分人使用的情况。

# ⽬标：
一个H5小工具，方便记账，旅行结束后给出计算后的费用分摊谁需要向谁支付多少钱，进一步可给出依据。轻量化，可以先不考虑数据泄露的问题，无需登录，无须用户和权限体系。尽量考虑纯前端项目，数据保存在前端。

# 范围：

## 必须做：

1. 记账模块，记录每个费用的用途、时间、谁支付、支付金额、受益人是哪几个；支持删除、修改记录
2. 旅行结束后，按结算按钮，自动计算谁需要向谁补支付多少钱，并可以给出计算整体依据
3. 旅行成员支持5人
4. 支持重新初始化数据，需要多次确认，防误触
5. 注意轻量化，去除所有不必要的功能，能自动初始化的数据初始化，能给选择的给选择，只能用户数据的才要求用户输入

## 可以做
1. 初始化项目时，设定旅行的人数，初始化各自的昵称
2. 账目防重，如果账目要素过于相似，提示不要重复记录
3. 实时当前的结算结果
4. 每日自动出一版当日的结算结果，和总开销情况，支出金额分类统计

## 本次不做
1. 数据后端存储
2. 短时间接口防重
3. 数据安全方面的考虑

2. 记账（多次记账）
